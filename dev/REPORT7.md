## 鍵盤實作與版面

- 第 1～4 區預設 `builtin`。`builtinMigrated` 隨存檔寫入，遷移完成後手動選回手機拼音會保留，既有英文模式也保留。
- 內建模式停用施法框焦點、手機鍵盤等待與 visualViewport 收鍵盤判斷，開始按鈕直接進入三秒倒數。真正切換分頁或視窗失焦仍透過遊戲狀態機暫停。
- 內建鍵盤 pointerdown 當下輸入，每個 pointerId 各有按鍵與氣泡狀態，長按維持一次輸入。鍵縫與邊緣以按鍵矩形的最近距離分配。禁止選取、callout、鍵盤區縮放與相容性 click 穿透。
- 加入 `key` 短音效及可關閉震動，震動 API 缺少或拒絕時安全略過。偷看、⌫ 與解除鎖定保留獨立按鍵。
- 鍵盤位於可視高度底部並包含 safe-area，戰場使用剩餘高度。360×640 鍵高約 43.59px，375×667 約 45.69px，390×844 與 430×932 約 46px。直向鍵盤高度約佔 30～31%。560px 與橫向使用縮小鍵高。
- 桌機預設隱藏內建鍵盤，字母鍵可直接施法。觸控裝置收到實體字母鍵後隱藏鍵盤，再次觸控可恢復。
- 第五區維持文字輸入及拼音選字。收起鍵盤時只出現一顆「點我繼續打字」，點下後同步 focus 並恢復倒數流程。

## 語音處理與驗證範圍

1. `scheduleSpeech` 與 `flushSpeech` 統一管理最新一句，避免每個輸入事件重設語音。新句開始後至少保留 110ms 才允許目標切換取消，平台取消後也至少等待 110ms 才 speak。
2. 目前、待播、解鎖 utterance 都保留模組層級參考，事件以 ticket 避免舊回呼污染新句。
3. speak 前檢查 paused 並 resume，分頁回前景及遊戲恢復也會 resume。
4. 靜音解鎖等待 onend，300ms 逾時則取消，接續真語音仍經過安全間隔。
5. 1.5 秒沒有 onstart 就取消並重試一次。兩次失敗留下「語音無回應」，遊戲繼續，後續正常 onstart 可清除該狀態。
6. 出怪、鎖定、打錯正解、王換題、第五區整句、題卡重聽、教學與暫停選單測試語音都經同一入口。倒數恢復時清除已唸標記，避免先前暫停取消的提示被誤當成播完。
7. 音樂 duck gain 使用既有 0.24 淡化。`audio.suspend()` 處理語音與音樂 gate，AudioContext 持續由手勢解鎖及 resume。替身測試檢查增益、音符釋放與語音呼叫順序。
8. 最近五筆紀錄含文字及 queued、start、end、error 與錯誤碼。靜音取消與被新句取代也會留下結果。

Web Speech API 的平台佇列、cancel、resume、paused、pending 與 utterance 事件依介面規格處理。110ms、300ms 與看門狗屬於這次依 TASK7 加入的防禦參數，iOS 引擎的實際發聲仍需真機確認。[Web Speech API 規格](https://webaudio.github.io/web-speech-api/#tts-section)

這次使用 headless Chrome、實際瀏覽器事件與語音／WebAudio 替身。我聽不到 headless 的聲音，無法把 speak/onstart 呼叫成功等同於 iPhone 已經能聽到語音。

## 真機驗證限制與殘留風險

- iPhone Safari、Telegram 的 WKWebView 與 iOS 內建拼音鍵盤的實際音訊輸出、語音引擎回呼可靠性、觸控延遲及工具列動態 safe-area，仍需實機核對。
- 語音引擎回報 onstart 後若裝置媒體音量、靜音鍵或 WebView 音訊政策使聲音不可聽，網頁只能記錄引擎事件，無法判定使用者是否聽見。
- 缺少 Vibration 的裝置使用音效與視覺回饋。震動強度與持續時間由裝置實作決定。
- HTML 加上快取提示與啟動版本比對。Telegram 或 Safari 外層快取仍需於實際網址確認，可用設定頁與偵錯面板的版本及建置時間辨識。
- 超過十分鐘的效能驗證使用加速模擬，包含實際 DOM 與回呼清理。iPhone 長時間背景切換、熱降頻及實體記憶體壓力需以真機觀察。
