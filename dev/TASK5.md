# 任務：《拼鬥魔法師》美術與介面精緻化

使用者原話：「目前的遊戲不夠精緻，設計上面再幫我優化」。前一輪（TASK4.md）已處理功能、特效、聲音；這一輪專做「看起來像一款完成度高的手機遊戲」。只在本資料夾工作；題庫與玩法邏輯不可改壞；selftest 與 browser-smoke 全部維持通過。先把 index.html 備份成 v4.html。不要 git、不要部署。結果寫 REPORT5.md。

## 允許的改變：可以使用圖片素材
- 不再限制單一檔。可新增 `assets/` 資料夾放圖片（webp 為主，單張 ≤ 200KB，總量 ≤ 6MB），index.html 以相對路徑載入。圖片載入失敗時要退回現有的 SVG 畫法，遊戲仍可玩。
- 用你內建的圖片生成能力產生素材（不要用網路上的現成圖、不要模仿任何既有遊戲或動畫的角色與風格）。若圖片生成不可用，停下來在 REPORT5.md 說明，並改以「大幅重畫 SVG」完成其餘項目。

## 美術方向（整套一致）
- 風格：明亮、溫暖的手繪童話繪本風，柔和的筆觸與乾淨的色塊，圓潤可愛但不幼稚；所有素材同一種筆觸、同一組色盤、同一個光源方向。先定一張風格基準圖（魔法師＋一隻怪＋草原場景）再據此產生其他素材，確保一致。
- 需要的素材：
  - 魔法師主角：待機、施法兩個姿勢（去背）。
  - 五個地區各：直式戰場背景一張（上方遠景、下方城門前的路；構圖要讓中段留給怪物、不可太花而干擾題卡閱讀）、一般怪 3 種（一般／快速／厚血）、王 1 隻（去背）。
  - 城門（完好／受損兩態）、地圖頁的主視覺（五個地區連成一條旅程的插圖）、遊戲標誌字「拼鬥魔法師」的標題圖、App 圖示（同時做 favicon 與 apple-touch-icon）。
  - 魔法彈、火球、爆炸、星星、金幣可繼續用程式畫，但顏色與風格要配合。
- 每張生成後自己檢查：有沒有多餘的文字或亂碼、肢體是否正常、去背是否乾淨、和基準圖風格是否一致；不合格就重生。最後把所有素材拼成一張總覽圖 assets/_overview.webp 供審查。

## 介面精緻化
- 重新設計整套介面元件，建立一致的設計系統（寫在 CSS 變數）：間距階層、圓角、陰影層次、字級階層（標題／內文／數字各有明確大小與字重）、按鈕三級（主要／次要／文字）、卡片、標籤、進度條、對話框。
- 地圖頁：改成「旅程地圖」而不是表單式卡片列表：五個地區沿著一條路排列，關卡節點有已通關／可挑戰／未解鎖三種清楚狀態，星等直接顯示在節點上；頂部是標題圖與玩家資訊（金幣、星數）；設定、對照表、小店、複習用圖示按鈕收在底部工具列（拇指區）。
- 戰鬥頁：HUD 做成遊戲感的元件（血條有邊框與漸層光澤、連擊有徽章），題卡像「怪物頭上的符咒牌」而不是白色表單卡；施法列像魔法卷軸或法陣輸入條。
- 教學、結算、小店、設定、暫停：統一成同一套面板樣式；結算要有儀式感（星星逐顆落下、分數滾動、破紀錄提示、魔法師慶祝姿勢）。
- 轉場：頁面切換、開場倒數、過關都有短而流暢的轉場動畫。
- 文字：全站文案重新潤飾，簡短、口語、有遊戲感；按鈕文字一律動詞開頭。
- 細節：所有圖示統一用同一套線條風格的內嵌 SVG；空狀態、讀取中、錯誤提示都要有設計過的樣子；按下回饋一致。
- 無障礙底線不變：文字對比 ≥ 4.5:1、可點目標 ≥ 44px、尊重 reduced-motion。
- 效能：首屏在 4G 手機上 3 秒內可互動；圖片 lazy-load（當前地區優先）、背景圖提供合適尺寸；動畫維持 60fps。
